# DeskPokemon for macOS

`DeskPokemon.app`을 일정한 위치(예: Applications)에 두고 실행하세요.
Dock에 표시되지 않는 데스크톱 펫이며, 포켓몬의 우클릭 메뉴에서 종료할 수 있습니다.

다른 앱을 사용하는 동안 키 입력·마우스 클릭에 맞춰 포켓몬이 반응하고 경험치를 얻으려면
macOS **시스템 설정 → 개인정보 보호 및 보안 → 입력 모니터링**에서 DeskPokemon을 허용하세요.
권한을 변경하면 앱은 자동으로 다시 확인합니다. 인식되지 않으면 **허용할 앱 확인**에서 현재 경로를 확인하고
해당 앱을 다시 추가한 뒤 완전히 종료·재실행하세요. 입력 문자열은 저장하거나 전송하지 않습니다.
허용하지 않아도 포켓몬 선택, 도감, 알 등 앱 화면을 사용할 수 있습니다.
개발 중 터미널에서 실행하면 권한 대상이 터미널 또는 dotnet 호스트로 표시될 수 있으므로
최종 확인은 `.app`으로 실행해서 진행하세요.

이 패키징 스크립트는 기본으로 로컬 테스트용 ad-hoc 서명을 적용합니다.
ad-hoc 서명은 재빌드하면 앱을 식별하는 서명 조건이 달라질 수 있어, 입력 모니터링의 기존 체크가
현재 빌드에도 적용된다고 보장하지 않습니다. 고정된 설치 위치만으로 이 차이가 없어지지는 않습니다.
[Apple TN3127](https://developer.apple.com/documentation/technotes/tn3127-inside-code-signing-requirements)에 따르면
ad-hoc 서명의 식별 조건은 특정 코드 버전에 묶입니다.

반복 빌드에서 서명 식별을 유지하려면 같은 번들 ID와 같은 실제 Apple Development 또는 Developer ID
인증서를 계속 사용하세요. 두 종류의 서명 사이를 바꾸면 권한 식별 조건도 달라질 수 있습니다.
패키징할 때 `MACOS_SIGNING_IDENTITY`에 키체인에 설치된 인증서의 실제 이름이나 SHA-1을 지정하면
해당 인증서로 내부 네이티브 라이브러리부터 앱까지 서명합니다. 지정한 인증서가 없거나 서명이 실패하면
패키징을 중단하며 ad-hoc으로 되돌아가지 않습니다. 인증서를 자동으로 생성·선택·설치하지 않습니다.

서명 옵션은 공증을 수행하지 않으며, 인증서를 지정한 것만으로 공개 배포 준비가 끝나지는 않습니다.
다운로드한 테스트 빌드가 차단되면 출처를 확인한 후 macOS 개인정보 보호 및 보안의
앱 실행 허용 절차를 따르세요. 공개 배포 전에는 Developer ID 서명과 공증이 필요합니다.
