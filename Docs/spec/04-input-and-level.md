# 입력 경험치와 레벨

## 입력 감지

Windows는 저수준 전역 훅, macOS는 읽기 전용 CGEventTap으로 다른 앱의 입력도 센다. Mac 입력 모니터링 허용을 확인하지 못하거나 연결이 실패하면 안내와 다시 연결 버튼을 표시하며, 앱 안의 키·클릭은 로컬 이벤트로 처리한다. 활성 전역 훅과 로컬 이벤트를 중복 계산하지 않는다. 입력 문자나 키 코드를 저장·전송하지 않는다.

### macOS 권한 확인과 복구

- 시작·창 활성화·자동 재시도는 권한 요청 창을 띄우지 않는다. `권한 요청` 버튼을 누른 경우에만 `IOHIDRequestAccess(ListenEvent)`를 호출한다. `다시 확인 / 연결`과 우클릭 `전역 입력 다시 연결`은 요청 없이 재확인한다.
- 연결되지 않은 동안 약 2초 간격으로 재확인한다. 시스템 설정에서 허용한 뒤 창으로 돌아오면 즉시 다시 시도한다. 같은 실패 상태를 유지하는 동안 안내를 시작 중 상태로 반복 전환하지 않는다.
- `CGPreflightListenEventAccess`와 `IOHIDCheckAccess(ListenEvent)` 중 하나가 허용이면 읽기 전용 tap 연결을 시도한다. KeyDown 전용 tap과 버튼·수식 키 tap을 같은 worker run loop에 연결하고 둘 다 유효·활성 상태여야 성공으로 표시한다. 키 권한이 없어 마우스만 연결된 상태를 전체 입력 성공으로 오인하지 않는다. 이미 정상 동작하는 tap은 권한 조회의 불일치만으로 해제하지 않는다.
- tap이 비활성화되거나 run loop가 중단되면 실제 연결을 정리하고 다시 시도한다. timeout은 재활성화 후 상태를 검사한다. 허용이 확인되는데 연결되지 않은 경우는 권한 없음과 구별해 연결 실패로 안내한다.
- `시스템 설정 열기`는 입력 모니터링 화면을 연다. `허용할 앱 확인`에서 현재 실행 중인 `.app`의 전체 경로를 확인·복사할 수 있다. 번들 밖에서 실행했다면 실제 실행 파일/`dotnet` 호스트 경로를 보여준다. 다른 위치의 같은 이름 앱을 허용한 것과 구분하기 위한 정보다.
- 표시 이름은 실제 번들과 같은 **DeskPokemon**이다. 개발용 ad-hoc 서명이 바뀐 빌드는 설정의 기존 체크와 현재 앱의 허용이 다를 수 있다. 이 경우 현재 경로의 앱 재등록·재실행을 안내한다. 앱은 권한 DB를 초기화하거나 설정을 대신 변경하지 않는다. 빌드 간 서명 조건은 [자산·배포 명세](08-assets.md)를 따른다.

권한 조회와 연결 오류·복구는 가짜 macOS backend로 회귀 테스트한다. 실제 OS 설정 변경에 따른 TCC 반영은 별도의 Mac 실기 확인이 필요하다. 구현 근거: [Apple Input Monitoring 안내](https://developer.apple.com/forums/thread/811443), [IOHIDCheckAccess](https://developer.apple.com/documentation/iokit/3181573-iohidcheckaccess), [Apple DTS의 IOHIDRequestAccess 안내](https://developer.apple.com/forums/thread/828052).

| 입력 | 경험치 반영 |
| --- | --- |
| 일반 키 누름 | 1회 |
| `Alt` 등 시스템 키 누름 | 1회 |
| 누른 키의 자동 반복 | 최초 1회만 |
| 키를 놓은 뒤 다시 누름 | 새 입력 1회 |
| 마우스 왼쪽·오른쪽·가운데 버튼 누름 | 각 1회 |
| 마우스 이동·휠 | 반영하지 않음 |

키 자동 반복은 현재 눌린 가상 키 목록으로 차단한다. 앱 종료 시 키보드·마우스 훅을 해제한다.

Debug의 [진화 수동 테스트 모드](09-developer-tools.md)에서는 전역 훅과 로컬 입력 경험치를 모두 비활성화한다. 일반 모드의 권한 부족 시 로컬 입력 대체 처리는 유지한다.

## 경험치 규칙

- 입력 1회당 현재 선택된 `모습 ID + 일반/이로치`에 연결된 육성 회차의 경험치가 1 증가한다. 지역 모습의 내부 ID는 전국도감 번호와 구분한다.
- 레벨 `n`에서 다음 레벨까지 필요한 경험치는 `30 × n`이다.
- 레벨업 시 요구 경험치를 차감하고 레벨을 1 올린다. 초과 경험치는 다음 레벨 진행도로 남는다.
- 레벨 1에서 레벨 `L`에 도달하는 누적 경험치는 `15 × (L - 1) × L`이다.

| 현재 레벨 | 다음 레벨 요구 경험치 | 해당 레벨까지 누적 경험치 |
| ---: | ---: | ---: |
| 1 | 30 | 0 |
| 2 | 60 | 30 |
| 5 | 150 | 300 |
| 10 | 300 | 1,350 |
| 26 | 780 | 9,750 |

누적 입력 10,000회면 `Lv.26`, 경험치 `250/780`이다.

## 육성 회차와 색상별 성장

- 성장 상태는 모습 ID에 연결된 육성 회차에 저장한다. `Settings.For(id, shiny)`가 `GrowthLinks` 또는 `ShinyGrowthLinks`를 따라 회차의 레벨·경험치를 반환한다.
- 한 회차에서 진화한 이전·현재 모습은 같은 성장 객체를 공유한다. 파이리→리자드 이후 파이리를 선택해 얻은 경험치도 같은 리자드 회차에 쌓인다. 현재 출발 모습을 선택해야 다음 단계로 진화한다.
- 같은 모습의 일반과 이로치는 회차·레벨·경험치를 공유하지 않는다. 도감에서 다른 회차의 포켓몬을 선택하면 이후 입력은 그 회차에 적용된다.
- 중복 부화는 보통 같은 색상 회차의 레벨을 즉시 1 올리고 기존 경험치를 유지한다. 그 회차에서 이미 분기를 거쳤고 미수집 직접 가지가 남은 기본형이 다시 부화하면 새 Lv.1·경험치 0 회차를 시작한다. 기존 진화형은 이전 회차에 남는다.
- 스키마 2의 종별 성장 기록은 마이그레이션 때 각각 독립 회차로 보존한다. 새로 진행하는 진화부터 회차를 공유한다. 재육성과 저장 구조는 [11-evolution.md](11-evolution.md), [07-save-data.md](07-save-data.md)를 따른다.

## 저장

- 입력마다 메모리 상태와 화면은 즉시 갱신한다.
- 디스크 쓰기는 최대 5초 단위로 모아 처리한다.
- 포켓몬 선택 변경은 즉시 저장한다.
- 창을 닫을 때 마지막 저장을 시도한다. 저장이 실패하면 오류를 표시하고 종료를 취소한다.

## 화면과 진화

- 경험치 바는 0 경험치에서도 마우스를 올리면 300ms 후 위쪽에 현재/필요 경험치를 표시한다. 레벨업 중 열린 툴팁의 수치도 갱신된다.
- 레벨업 후 현재 회차의 진화 가능 여부를 확인한다. 현재 출발 모습이면 대상 확정·선저장 후 자동 진화하고, 이전 모습이면 출발 모습·세대로 안내한다. 분기는 해당 색상의 미수집 직접 후보 중 무작위로 정하며 자세한 조건은 [진화 명세](11-evolution.md)를 따른다.
- 진화 연출 중에도 경험치는 같은 회차에 쌓이고 본체 바운스만 억제한다.
