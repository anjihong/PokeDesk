# 진화·지역 모습·분기 재육성

> 2026-09-28 구현. 스키마 3, 기본 1,025종과 추가 모습 11개를 대상으로 한다.

## 확정 규칙

- 원작 진화 관계와 지역 모습을 유지하며 조건은 레벨로 통일한다.
- 고정 레벨이 없으면 첫 진화 25, 두 번째 진화 40을 적용한다. 친밀도도 동일하다.
- 분기 공통 레벨: 야돈 37, 킬리아 30, 토중몬 20, 눈꼬마 42.
- 첫 분기는 균등 무작위다. 재육성에서는 미수집 대상을 선택하며 하나만 남으면 자동 결정한다.
- 이브이는 진화하지 않고 진화체 8종은 알에서 독립적으로 획득·육성한다.
- 일반·이로치의 보유·성장·분기 이력은 독립이다.

## 지역 모습

기존 1,025종에 가라르 지그제구리·직구리·나옹·코산호·파오리·마임맨·데스마스, 히스이 포푸니·침바루, 팔데아 우파, 흰줄무늬 배쓰나이를 추가한다. 수집 대상은 총 1,036개다. 추가 모습은 등장 세대인 8·9세대에 별도 칸으로 표시한다.

가라르 지그제구리는 직구리·가로막구리로 이어진다. 흉내내는 25에 일반·가라르 마임맨으로 분기하며 가라르 마임맨은 42에 마임꽁꽁으로 진화한다. 다른 지역 전용 종도 해당 모습에서만 진화한다. 추가 계열의 기본형만 알에 포함한다. 지역 이미지 실패 시 일반 모습으로 대체하지 않는다.

## 육성 기록과 중복 부화

같은 육성에서 거친 모습은 레벨·경험치를 공유한다. 모습당 도감 칸은 하나다.

| 부화 직전 상태 | 결과 |
| --- | --- |
| 첫 획득 | Lv.1, 경험치 0 |
| 이번 육성의 분기 미완료 | 레벨 +1, 경험치 유지 |
| 이번 분기 완료, 미수집 가지 있음 | 기본형 새 Lv.1, 경험치 0 |
| 모든 가지 수집 완료 또는 비분기 계열 | 레벨 +1, 경험치 유지 |

새 기본형은 기존 진화체와 독립 성장한다. 중간 모습은 새 육성이 도달했을 때 새 기록에 연결한다. 예: 가디안 보존, 랄토스 재부화 Lv.1, 킬리아 재진화, 엘레이드 획득. 개무소의 기존 실쿤·뷰티플라이와 새 카스쿤·독케일도 독립이다. 분기 완료는 직접 분기 대상 획득 기준이다.

부화 레벨 보너스로 조건을 충족하면 보너스 적용 후 진화하며 같은 부화에서 초기화하지 않는다.

## 화면과 저장

현재 모습이 이번 육성의 진화 단계면 자동 진화한다. 이전 모습 선택 중이면 머리 위 알림과 출발 모습·세대 탭 강조를 표시한다. 출발 모습을 선택하면 진화한다. 재육성 선택창을 닫으면 진화 가능 상태를 유지한다. 짧은 점멸 후 진화체를 자동 선택하며 이전 모습도 계속 선택 가능하다.

선택창을 닫은 육성은 입력으로 창을 반복해서 열지 않는다. 진화 가능 버튼 또는 출발 모습의 재선택으로 다시 연다. 이전 모습에서 진화 가능 버튼을 누르면 해당 색상·세대의 도감을 연다. 진화 레벨 이상이면 이미 조건을 넘긴 상태에서도 진화하며, 여러 단계가 가능하면 한 단계씩 처리한다.

무작위 대상은 진화 시작 시 저장한다. 이미지 실패나 재시작으로 재추첨하지 않는다. 부화·진화 저장 실패는 상태를 복원하고, 늦게 끝난 이미지 요청은 선택을 덮어쓰지 않는다.

스키마 3으로 이전한다. 기존 종별 기록은 독립 육성으로 보존하며 신규 진화부터 공유한다. 기존 선택·색상·확정 알을 보존하고 원본을 백업한다.

기존 모델·WPF 테스트에 레벨 경계, 지역 연결, 분기 재육성, 색상 분리, 데이터 이전, 저장 실패, 비동기 선택, 확정 알 유지, 강조와 자동 선택 검증을 추가했다. 테스트는 임시 저장 파일을 사용하며 실제 사용자 저장 파일을 바꾸지 않는다.

Debug 빌드의 [진화 수동 테스트 도구](09-developer-tools.md#진화-수동-테스트)는 별도 세이브에서 분기·지역 기본형의 알을 지정하고 다음 진화 레벨로 이동한다. 이전 모습을 선택한 채 레벨을 올려 알림과 도감 강조를 확인할 수 있다. 지정 알도 기존 부화·중복·재육성 흐름을 사용한다.

검증 명령(각각 Debug·Release 실행):

```powershell
dotnet build -c Debug -o bin/Debug/shiny-preview
dotnet run --project tests/DeskPokemon.ModelTests -c Debug
dotnet run --project tests/DeskPokemon.UiTests -c Debug
```

WPF 테스트에 `-- --evolution-assets`를 붙이면 실제 네트워크로 전체 도감 아이콘과 추가 모습 11개의 일반·이로치 애니메이션을 확인한다. `bin/ui-verification/`에 진화 알림과 지역 도감 렌더링을 남긴다. 테스트 도중 진화 후보 선택창을 자동으로 열고 닫으며 입력 훅은 시작하지 않는다.

검증 결과: Debug·Release 빌드 경고·오류 0개, 모델 검사 각각 2,707개·2,687개 통과, WPF 검사 각각 98개·78개 통과. 실제 자산을 포함한 Release WPF 검사는 110개 통과했으며 전체 1,036개 아이콘과 추가 모습 11개의 일반·이로치 다중 프레임을 확인했다.
