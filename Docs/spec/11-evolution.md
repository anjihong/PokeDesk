# 진화·지역 모습·분기 재육성

## 진화 조건

- 기본 1,025종과 지역 모습 11개, 총 **1,036개 모습**의 진화 관계를 지원한다. 일반·이로치의 보유와 육성 회차는 독립이다.
- 원작에 고정 레벨이 있으면 해당 값을 사용한다. 파이리→리자드 16, 리자드→리자몽 36이다.
- 고정 레벨이 없는 친밀도·돌·교환·기술·특수 조건은 첫 진화 25, 두 번째 진화 40으로 대체한다. 피츄→피카츄는 25, 피카츄→라이츄는 40이다. 시간·성별·지역·아이템 등의 추가 제한은 적용하지 않는다.
- 분기 공통 레벨은 **이브이 25, 야돈 37, 킬리아 30, 토중몬 20, 눈꼬마 42**로 통일한다.
- 분기는 첫 진화와 재육성 모두 해당 색상의 **미수집 직접 후보 중 균등 무작위**로 선택한다. 하나만 남으면 그 결과로 확정한다. 사용자에게 가지를 고르는 창을 띄우지 않는다.
- 이브이는 Lv.25에 샤미드·쥬피썬더·부스터·에브이·블래키·리피아·글레이시아·님피아 중 하나로 진화한다. 8개 진화형은 새 알 후보에서 제외한다. 구버전 보유와 이미 확정된 진화형 알은 보존한다.
- Debug 전체 해금은 영구 보유나 진화 자격을 만들지 않는다. 해당 색상의 실제 보유와 회차가 필요하다.

## 육성 회차와 이전 모습

진화는 이전 모습의 보유를 소비하지 않는다. 같은 회차에서 거친 모습들은 **동일한 레벨·경험치**를 공유하며 언제든 이전 모습을 선택할 수 있다. 이번 회차가 마지막으로 도달한 모습은 `CurrentDex`, 거친 모습은 `History`에 기록한다.

1. 파이리 Lv.16→리자드 진화 후 두 모습을 모두 보유하고 같은 회차를 참조한다.
2. 파이리를 다시 선택해 Lv.36까지 키우면 리자드 회차도 Lv.36이다. 파이리에서 바로 리자몽으로 건너뛰지 않는다.
3. 이전 모습을 선택 중이면 머리 위 안내와 실제 출발 모습·세대 탭 강조를 표시한다. 안내를 누르면 해당 색상·세대의 도감을 연다.
4. 현재 회차의 출발 모습인 리자드를 선택하면 리자몽 진화를 시작한다.
5. 이미 레벨을 넘겼거나 한 번에 여러 단계가 가능해도 한 단계씩 연출·저장한다. 다음 현재 모습이 계속 조건을 충족하면 이어서 진행한다.

스키마 2에서 이미 별도로 키운 모습들은 마이그레이션만으로 합치지 않는다. 기존 종별 레벨·경험치는 독립 회차로 유지하고 새로 진행하는 진화부터 공유한다.

## 분기 재육성과 중복 부화

| 같은 색상 기본형의 부화 직전 상태 | 결과 |
| --- | --- |
| 첫 획득 | 새 Lv.1·경험치 0 회차 |
| 이번 회차의 분기를 아직 지나지 않음 | 기존 회차 레벨 +1, 경험치 유지 |
| 이번 회차에서 분기 완료, 미수집 직접 가지 있음 | 기본형에 새 Lv.1·경험치 0 회차 연결 |
| 모든 가지 수집 완료 또는 비분기 계열 | 기존 회차 레벨 +1, 경험치 유지 |

분기 완료는 직접 분기 대상을 얻었는지로 판정한다. 개무소→실쿤 후 새 개무소 알로 재육성을 시작해도 실쿤 회차는 계속 자라 뷰티플라이로 진화할 수 있다. 새 개무소는 별도 회차에서 카스쿤→독케일을 얻는다.

랄토스→킬리아→가디안 이후 랄토스가 다시 부화하면 새 Lv.1 회차를 시작한다. 기존 가디안·킬리아는 이전 회차에 남고 새 랄토스가 킬리아에 도달했을 때 킬리아의 연결을 갱신한다. 이후 미수집 엘레이드로 진화한다. 이미 보유한 중간 모습도 새 회차가 도달하면 연결할 수 있지만 추가 레벨 보상은 없다.

이브이도 같은 규칙으로 8개 진화형을 모은다. 전부 모은 뒤의 중복 이브이는 가장 최근 회차에 레벨 보너스를 준다. 일반 8종과 이로치 8종의 수집·재육성 판정은 독립이다. 부화 보너스로 처음 진화 레벨에 도달한 경우 그 부화는 보너스로 처리하고, 진화 이후의 다음 기본형 부화부터 재육성 여부를 판단한다.

## 진화 연출과 저장 경계

1. **로딩 전에** `PrepareEvolution`이 직접 후보를 무작위 확정하고 `PendingEvolution`에 원자적으로 저장한다. 저장된 대상이 있으면 다시 뽑지 않는다.
2. 같은 지역 모습·색상의 목표 아틀라스를 로드한다. 일반은 일반, 이로치는 이로치 이미지이며 로딩 중에는 기존 포켓몬을 유지한다.
3. 약 **2.2초** 동안 준비 빛과 흰색 원본 실루엣을 표시한 뒤 원본·목표 실루엣의 비중을 점진적으로 바꾸고 약한 맥동을 적용한다.
4. 실루엣 전환이 끝나면 `CompleteEvolution`으로 대상 보유·회차 연결·현재 모습·이력·선택을 한 번에 원자적으로 저장한다.
5. 성공 후 약 **0.6초** 동안 목표의 실제 색상을 드러낸다. 총 연출은 약 **2.8초**이며 로딩·저장 시간은 별도다.

두 모습의 실제 발을 같은 그림자 중심에 맞춘다. 정상 본체와 진화 목표에 같은 종별 크기 정책을 적용한다. 목표 높이는 종 높이를 완만하게 반영한 약 92~120 DIP 범위이며 파이리/리자드/리자몽은 96/106/114 DIP다. 넓은 몸체의 폭 제한과 반전·프레임별 발 정렬은 [03-pet-display.md](03-pet-display.md)를 따른다. 흰 실루엣은 연출용이며 마지막에는 원래 색상을 표시한다.

준비·로딩부터 마무리까지 중복 진화, 다른 포켓몬 선택, 알 클릭을 막는다. 전역 입력 경험치는 계속 수집하고 바운스만 억제한다. 진화 전후 선택은 같은 회차이므로 연출 중 얻은 경험치도 그 회차에 남는다.

## 실패·취소·재시작

- 준비 저장이 실패하면 새 예약 대상을 취소하고 진화를 시작하지 않는다.
- 목표 로드 또는 완료 저장 실패 시 오류를 표시하고 기존 스프라이트를 완전히 복원한다. 이미 저장된 예약 대상은 유지하여 다음 시도에도 같은 결과를 사용한다.
- 완료 저장 실패는 대상 보유·회차 연결·현재 모습·이력·선택 번호·색상을 되돌린다. 이전 진화체, 다른 색상, 알 결과는 바꾸지 않는다.
- 창을 닫아 **완료 저장 전** 연출이 취소되면 새 형태의 지급·선택은 발생하지 않는다. 먼저 저장한 `PendingEvolution`은 남으며 다음 실행에서 재추첨하지 않는다. 입력으로 얻은 경험치는 기존 저장 규칙을 따른다.
- **완료 저장 후** 색상 공개 중 닫으면 성공한 진화와 같은 색상 선택을 유지한다. 연출 취소 때문에 이미 저장한 결과를 되돌리지 않는다.
- 종료·실패 시 효과와 임시 비트맵을 정리한다. 늦게 끝난 로드는 새 선택을 덮어쓰지 않는다.

스키마 3의 회차 구조, 이전 버전 백업과 손상 보호는 [07-save-data.md](07-save-data.md)를 참고한다.

## API

| API | 역할 |
| --- | --- |
| `EvolutionData.Forms`, `Form(id)`, `NationalDex(id)` | 지역 모습 카탈로그와 전국도감 매핑 |
| `EvolutionData.From(id)`, `IsBranch(id)`, `EggPool` | 직접 규칙·분기 여부·새 알 후보 |
| `EvolutionRules.OptionsFor(id)` | 직접 후속 `(TargetDex, RequiredLevel)` 조회 호환 API |
| `Settings.For(id, shiny)` | 색상별 연결된 회차의 성장 객체 |
| `Settings.EvolutionOptions(id, shiny)` | 선택한 이전 모습에서도 현재 회차의 출발 `FromId`와 준비된 후보 조회 |
| `Settings.AvailableEvolutions(id, shiny)` | 해당 ID가 현재 출발 모습일 때만 직접 후보 조회 |
| `Settings.PrepareEvolution(id, shiny, target?, random?)` | 대상 확정·선저장. 실제 UI는 명시 대상 없이 무작위 선택 |
| `Settings.CompleteEvolution(id, shiny, target)` | 예약된 한 단계 지급·회차 연결·선택·원자적 저장 |
| `Settings.Evolve(id, target, shiny)` | 준비·완료를 함께 호출하는 호환/테스트 API |
| `PokemonDetails.For(id)` | 종 또는 지역 모습의 내장 한국어 설명·타입 |

## 데이터 출처와 재생성

[PokeAPI 공식 저장소](https://github.com/PokeAPI/pokeapi/tree/168b1e89467054cda2e7df43ccebbb69b459497a/data/v2/csv)의 커밋 `168b1e89467054cda2e7df43ccebbb69b459497a`에 고정한다. `Assets/Data/sources.json`에 CSV별 SHA-256과 변환 규칙을 기록한다.

- `pokemon_species.csv`, `pokemon_forms.csv`, `pokemon.csv`: 종·지원 기본/지역 모습·진화 깊이.
- `pokemon_evolution.csv`: **486개 직접 진화 관계**와 원작 레벨. `levelSource`는 원작·대체·분기 공통 조정을 구분하며 원본 행 ID도 남긴다.
- `pokemon_types.csv`, `type_names.csv`: 각 기본/지역 모습의 실제 한국어 타입.
- `pokemon_species_flavor_text.csv`, `versions.csv`: 한국어 설명 중 가장 최근 버전. 줄바꿈은 공백으로 정리한다.
- `pokemon_species_names.csv`: 한국어 분류명.

기본 1,025종 중 **#899~1025의 127종은 원본에 한국어 도감 문장이 없다.** 해당 종에는 출처의 분류·타입만 표시한다. 지역 모습 11개도 다른 폼의 설명을 잘못 붙이지 않도록 해당 폼의 실제 타입과 종 분류를 사용한다. 따라서 1,036개 상세 중 898개는 한국어 도감 문장, 138개는 명시된 분류·타입 메타데이터이며 내용을 창작하지 않는다.

`tools/generate_evolutions.py`를 진화 규칙·지역 모습·원본 커밋의 단일 원본으로 사용한다. `scripts/generate-pokemon-data.py`는 이 main 생성기를 불러와 해시를 검증한 로컬 CSV를 공급하고, 같은 실행에서 한국어 상세와 출처 명세도 생성한다. main 생성기 파일과 알고리즘을 별도로 복제하지 않는다.

기본 모습과 지역 모습의 연결을 구별한다. 비비용 meadow는 원본의 같은 종·레벨 무늬 연결을 앱 기본 모습 하나로 모은다. 생성기는 중복·충돌·순환·최대 깊이와 550개 알 후보에서 전체 1,036개 모습의 획득 가능성을 검사한다. 런타임 상세·진화 조회에는 네트워크가 필요 없다.

```sh
python3 scripts/generate-pokemon-data.py --download
# 고정 CSV가 이미 있으면 오프라인 재생성:
python3 scripts/generate-pokemon-data.py --source-dir /path/to/csv
```

기존 출처 명세와 CSV 체크섬이 다르면 생성을 중단한다. Debug 진화 도구는 [09-developer-tools.md](09-developer-tools.md)를 참고한다.
