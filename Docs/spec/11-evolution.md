# 레벨 진화와 오프라인 도감 데이터

## 진화 조건

- 전국도감 1~1025종의 직접 진화 관계를 사용한다. 일반과 이로치는 별도로 진화한다.
- 원작 데이터에 최소 진화 레벨이 있으면 그 레벨을 사용한다. 예: 파이리→리자드 16, 리자드→리자몽 36.
- 최소 레벨이 없는 친밀도·돌·교환·기술·특수 조건은 이 앱에서 첫 진화 25, 두 번째 진화 40으로 대체한다. 베이비를 포함한 진화 트리의 깊이를 기준으로 한다. 피츄→피카츄는 25, 피카츄→라이츄는 40이다.
- 여러 게임/폼에 조건이 있으면 일반 결과 폼의 기록을 우선하고, 그중 명시된 최소 레벨을 사용한다. 일반 결과 기록이 없는 별도 종은 해당 종의 기록을 사용한다. 성별·시간·지역·아이템 등의 추가 제한은 적용하지 않는다.
- 분기 진화는 조건을 충족한 직접 후속 종 중 사용자가 고른 한 종을 얻는다. 이미 보유한 후속 종은 다시 진화 대상으로 제시하지 않는다. 다른 미보유 분기는 나중에 선택할 수 있다. 전체 직접 진화 경로가 두 개 이상인 종은 미보유 경로가 하나만 남아도 자동 진화하지 않고 사용자의 명시적 선택을 기다린다. 예를 들어 실쿤을 얻은 뒤 개무소를 다시 선택해도 자동으로 카스쿤이 되지 않는다.
- 이브이는 진화하지 않는다. 샤미드·쥬피썬더·부스터·에브이·블래키·리피아·글레이시아·님피아는 이브이와 별개로 알 후보에 포함한다. 알 등급 및 이로치 확률은 기존과 같다.
- Debug 전체 해금은 실제 진화 자격이나 보유 목록을 만들지 않는다. 진화에는 해당 색상의 실제 보유가 필요하다.

## 이전 형태를 다시 키우는 규칙

진화는 이전 종을 소비하지 않는다. 이전 형태와 성장 기록은 그대로 남으므로 언제든 도감에서 다시 선택할 수 있다.

한 형태의 진화 자격은 **같은 색상의 보유한 자신과 조상 중 가장 높은 레벨**을 기준으로 한다. 형제 분기와 다른 색상의 성장은 공유하지 않는다. 이 계산은 기존 성장 기록을 바꾸지 않는다.

예:

1. 파이리 Lv.16을 리자드로 진화하면 두 형태를 모두 보유하고 리자드를 선택한다.
2. 도감에서 파이리를 다시 선택하고 Lv.36까지 키워도 바로 리자몽으로 건너뛰지 않는다. 이미 보유한 리자드로 반복 진화하지도 않는다.
3. 보유 리자드는 파이리의 Lv.36을 진화 조건으로 사용할 수 있다. UI에서 진화 가능을 안내하고 리자드를 선택하면 리자몽 진화를 시작한다.
4. 모델의 `Evolve` 한 번은 항상 직접 후속 한 단계만 처리한다. 고레벨 개체도 한 호출로 연속 단계를 건너뛰지 않는다.

## 진화 후 성장 및 선택

- 새 형태는 같은 색상의 보유한 자신·조상 중 `(Level, Exp)`가 가장 큰 기록을 복사한다. 먼저 레벨을 비교하고, 레벨이 같으면 현재 경험치가 큰 기록을 사용한다.
- 새 형태와 이전 형태의 `PokemonProgress` 객체는 독립적이다. 진화 이후 경험치는 현재 선택한 개체에만 쌓인다.
- 대상 종의 보유 없이 남은 복구용 성장 기록이 더 높다면 그 기록을 보존한다.
- 진화 전 형태가 현재 선택된 같은 색상 개체인 경우 새 형태를 선택하고 색상은 유지한다. 다른 개체를 처리하는 모델 호출은 현재 선택을 바꾸지 않는다.
- 이미 보유한 대상 종으로 반복 호출해도 레벨 증가 등의 보상은 없다.
- 자격을 충족하지 않거나 직접 후속 종이 아니면 `Evolve`는 `null`을 반환하고 상태와 저장 파일을 바꾸지 않는다.

## 저장과 실패 복구

새 종 보유, 성장 복사, 현재 선택 변경을 한 번의 원자적 파일 교체로 저장한다. 저장에 실패하면 보유 목록·대상 성장 객체·선택 번호·선택 색상을 모두 이전 상태로 복구하고 예외를 UI에 전달한다. 이전 형태, 알 결과, 다른 색상의 데이터는 변경하지 않는다.

진화는 기존 `Owned`/`Progress`와 `ShinyOwned`/`ShinyProgress`를 사용하므로 별도 저장 스키마 변경이 필요하지 않다. 스키마 2 저장을 유지한다. 진화 연출과 이미지 로드 실패는 UI에서 처리하고, 저장된 진화 결과를 임의로 다시 추첨하지 않는다.

## API

| API | 역할 |
| --- | --- |
| `EvolutionRules.OptionsFor(dex)` | 레벨 충족·보유 여부와 무관한 직접 후속 `(TargetDex, RequiredLevel)` 목록 |
| `Settings.EffectiveEvolutionLevel(dex, shiny)` | 같은 색상 보유 조상의 성장까지 고려한 조건용 레벨 |
| `Settings.AvailableEvolutions(dex, shiny)` | 실제 보유 형태의 조건을 충족한 미보유 직접 후속 목록 |
| `Settings.CanEvolve(dex, shiny)` | 위 목록이 비어 있지 않은지 확인 |
| `Settings.Evolve(dex, target, shiny)` | 한 단계 지급·선택·원자적 저장, 성공 시 `EvolutionResult` |
| `PokemonDetails.For(dex)` | 해당 종의 내장 한국어 `Description`, `Types` |

## 데이터 출처 및 재생성

[PokeAPI 공식 저장소](https://github.com/PokeAPI/pokeapi/tree/168b1e89467054cda2e7df43ccebbb69b459497a/data/v2/csv)의 커밋 `168b1e89467054cda2e7df43ccebbb69b459497a`에 고정했다. `Assets/Data/sources.json`에 입력 CSV별 SHA-256과 적용한 변환 규칙을 기록한다.

- `pokemon_species.csv`: 부모 종과 진화 단계.
- `pokemon_evolution.csv`: 직접 후속 종별 최소 레벨. 476개 앱 진화 관계를 생성한다.
- `pokemon.csv`, `pokemon_types.csv`, `type_names.csv`: 기본 폼의 한국어 타입.
- `pokemon_species_flavor_text.csv`, `versions.csv`: 한국어 설명 중 버전 번호가 가장 큰 항목. 줄바꿈·페이지 구분 문자는 공백으로 정리한다.
- `pokemon_species_names.csv`: 한국어 분류명.

PokeAPI의 해당 스냅샷에는 **#899~1025, 127종의 한국어 도감 문장이 없다.** 이 종은 문장을 창작하거나 임의 번역하지 않고 공식 데이터에 있는 `분류: …`와 `타입: …`를 표시한다. `MetadataOnly`와 원문 버전은 JSON에 명시한다. 나머지 898종은 한국어 도감 문장을 표시한다.

모든 1,025종의 데이터는 JSON으로 내장하므로 상세 정보와 진화 규칙 조회에 네트워크가 필요 없다. 스프라이트·아이콘 다운로드는 기존 경로를 사용한다.

```sh
python3 scripts/generate-pokemon-data.py --download
# 이미 받은 고정 버전 CSV로 오프라인 재생성:
python3 scripts/generate-pokemon-data.py --source-dir /path/to/csv
```

기존 출처 명세가 있는 경우 CSV 체크섬이 다르면 생성을 중단한다. 데이터 갱신 시에는 커밋·출처·검증 결과를 함께 갱신한다.
