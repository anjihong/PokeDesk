# 저장 데이터

저장 위치: Windows `%LOCALAPPDATA%\DeskPokemon\settings.json`, macOS `~/Library/Application Support/DeskPokemon/settings.json`

| 필드 | 의미 |
| --- | --- |
| `SchemaVersion` | 저장 형식 버전. 현재 값 `2` |
| `StarterDex` | 최초 선택한 스타팅의 도감 번호 |
| `SelectedDex` | 현재 화면에 표시할 포켓몬의 도감 번호 |
| `SelectedShiny` | 현재 선택이 이로치인지 여부 |
| `FlipHorizontal` | 메인 포켓몬 좌우 반전. 기본값 `false` |
| `UiScale` | UI 배율 단계 `2`, `4`, `6`, `8`. 기본값 `2` |
| `Progress`, `Owned` | 일반 포켓몬의 도감 번호별 성장 상태와 보유 목록 |
| `ShinyProgress`, `ShinyOwned` | 이로치 포켓몬의 도감 번호별 성장 상태와 보유 목록 |
| `Eggs` | 보유 알 수. 정상 흐름에서는 `0` 또는 `1` |
| `EggSeconds` | 다음 알까지 누적한 실행 시간(초) |
| `PendingEgg` | 확정된 다음 알의 `Kind`, `Dex`, `IsShiny` |

`UnlockAll`과 `RemainingEggSeconds`는 계산·개발용 속성이며 JSON에 저장하지 않는다.

## 데이터 관계

- `SelectedDex`와 `SelectedShiny`를 한 쌍으로 현재 개체를 식별한다.
- `Progress[dex]`는 일반 개체의 `Level`, `Exp`를 저장한다.
- `ShinyProgress[dex]`는 같은 번호 이로치 개체의 `Level`, `Exp`를 따로 저장한다.
- `Owned`와 `ShinyOwned`도 서로 독립된 집합이다.
- 진화도 같은 색상의 보유·성장 목록을 사용한다. 이전 형태는 남기고, 새 형태에는 같은 색상의 자신·보유 조상 중 가장 큰 `(Level, Exp)`를 복사한다. 별도 스키마 필드를 추가하지 않는다.
- `PendingEgg`는 `Eggs`가 0인 대기 중에도 다음 결과를 유지한다.
- `Eggs`가 1이면 타이머를 멈추고 같은 `PendingEgg`를 부화한다.

## 저장 시점

| 변경 | 저장 시점 |
| --- | --- |
| 입력 경험치 | 변경 표시 후 최대 5초 안에 일괄 저장 |
| 알 대기 시간 | 메모리에서 매초 증가, 주기 저장 |
| 알 준비 완료 | 즉시 저장 |
| 도감 포켓몬 선택 | 즉시 저장 |
| 부화 결과·다음 알 결과 | 하나의 작업으로 즉시 저장 |
| 진화 보유·성장·선택 | 하나의 작업으로 즉시 저장 |
| 좌우 반전·UI 배율 | 변경 시 즉시 저장 |
| 창 종료 | 종료 직전 저장 |

저장은 같은 폴더에 임시 파일을 만든 뒤 `settings.json`을 교체한다. 기존 파일을 직접 쓰는 중간 상태를 만들지 않는다. 임시 파일은 성공·실패와 관계없이 정리한다.

## 값 보정

- `Eggs`는 `0~1` 범위로 제한한다.
- `EggSeconds`는 유한한 값만 허용하고 `0~1800`초로 제한한다.
- 스타팅은 항상 일반 `Owned`에 포함한다.
- 현재 선택이 해당 색상 보유 목록에 없으면 일반 스타팅으로 되돌린다.
- `PendingEgg`의 등급이나 종이 유효하지 않으면 새 결과를 만든다. 유효한 기존 결과는 부화 후보 추가나 앱 재시작으로 다시 추첨하지 않는다. 이브이의 여덟 진화형도 유효한 알 후보다.
- `UiScale`이 `2`, `4`, `6`, `8` 중 하나가 아니면 `2`로 보정한다. 반전 값이 없는 구버전 저장은 `false`, 배율 값이 없는 저장은 `2`를 사용한다.

- 구버전은 마이그레이션 전 원본을 `settings.json.schema{버전}.bak`으로 한 번 백업한다.
- 스키마 1 저장은 일반 보유·성장 데이터를 유지하고 이로치 데이터를 빈 상태로 추가한다. 기존 준비 알은 커먼 알로 변환하고 결과를 한 번 확정한다.
- 스타팅 번호가 없으면 파이리로 보정한다. 선택 종이 해당 색상에서 미보유면 일반 스타팅으로 되돌린다.
- 저장은 임시 파일 작성 후 원본 교체 방식이다. 부화 저장 실패 시 메모리 상태도 복구한다. 진화 저장 실패 시 추가한 보유·성장과 선택 번호·색상을 복구한다. 알 상태나 이전 형태의 성장은 바꾸지 않는다.
- 손상된 JSON, JSON `null`, 배열·숫자처럼 설정 객체가 아닌 JSON은 원본을 보존하고 불러오기 오류를 표시한다. 새 게임으로 오인해 덮어쓰지 않는다. 파일 자체가 없는 경우에만 새 게임을 시작한다. 현재 앱보다 새 스키마는 덮어쓰지 않고 오류와 함께 종료한다.

## 스키마 2 호환성

진화와 화면 설정은 기존 스키마 2를 유지한다. 선택·보유·경험치·확정 알이 유효한 기존 스키마 2 저장은 새 설정 필드가 없어도 그대로 읽으며, 단순 조회만으로 파일을 다시 쓰지 않는다. 새 설정 필드는 다음 정상 저장부터 함께 기록한다. 구버전 마이그레이션 백업과 미래 스키마 덮어쓰기 차단은 유지한다.

진화 조건 및 복사되는 성장 기록의 자세한 규칙은 [11-evolution.md](11-evolution.md)를 참고한다.
