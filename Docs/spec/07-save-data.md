# 저장 데이터

저장 위치: Windows `%LOCALAPPDATA%\DeskPokemon\settings.json`, macOS `~/Library/Application Support/DeskPokemon/settings.json`

| 필드 | 의미 |
| --- | --- |
| `SchemaVersion` | 저장 형식 버전. 현재 값 `3` |
| `StarterDex` | 최초 선택한 스타팅 번호 |
| `SelectedDex`, `SelectedShiny` | 현재 표시할 모습 ID와 색상 |
| `FlipHorizontal` | 메인 포켓몬 좌우 반전. 기본값 `false` |
| `UiScale` | UI 배율 단계 `2`, `4`, `6`, `8`. 기본값 `2` |
| `Owned`, `ShinyOwned` | 일반·이로치의 독립된 보유 모습 ID 집합 |
| `Progress`, `ShinyProgress` | 색상별 육성 **회차 ID**를 키로 하는 성장 기록 |
| `GrowthLinks`, `ShinyGrowthLinks` | 모습 ID → 해당 색상의 육성 회차 ID 연결 |
| `Eggs` | 준비된 알 수 `0` 또는 `1` |
| `EggSeconds` | 다음 알까지 누적한 실행 시간(초) |
| `PendingEgg` | 확정된 다음 알의 `Kind`, `Dex`, `IsShiny` |

`UnlockAll`과 `RemainingEggSeconds`는 계산·개발용 속성이며 JSON에 저장하지 않는다. 지원 대상은 기본 1,025종과 지역 모습 11개, 색상별 1,036개다. 지역 모습 내부 ID는 전국도감 번호와 다르다.

## 육성 회차와 연결

`PokemonProgress`는 `Level`, `Exp`, `CurrentDex`, `History`, `PendingEvolution`을 저장한다.

- `Level`·`Exp`: 같은 회차에서 거친 모습이 공유하는 성장.
- `CurrentDex`: 이번 회차가 마지막으로 도달한 모습.
- `History`: 이번 회차가 거친 모습 ID 순서.
- `PendingEvolution`: 이미지 로딩 전에 무작위 확정·저장한 다음 대상. 미확정 또는 완료 후에는 `null`.
- 일반은 `Progress[GrowthLinks[id]]`, 이로치는 `ShinyProgress[ShinyGrowthLinks[id]]`로 조회한다. 레코드 키를 종 번호로 해석하면 안 된다.
- 새로운 진화는 대상 모습을 기존 회차에 연결하고 `CurrentDex`·`History`를 갱신한다. 이전 모습의 보유와 연결은 유지한다.
- 분기 재육성은 기본형에 새 Lv.1 회차를 연결한다. 기존 진화형은 이전 회차에 남는다. 새 회차가 중간 모습에 도달할 때 그 모습의 연결을 갱신한다.
- 두 색상의 회차 ID가 같더라도 서로 다른 기록이다. 보유·성장·분기 완료와 예약 대상은 색상 사이에 공유하지 않는다.
- `PendingEgg`는 대기 중에도 유지하며 `Eggs=1`일 때 같은 결과를 부화한다.

## 저장 시점과 원자성

| 변경 | 저장 시점 |
| --- | --- |
| 입력 경험치·알 대기 시간 | 변경 표시 후 최대 5초 안에 일괄 저장 |
| 알 준비 완료·도감 선택 | 즉시 저장 |
| 부화 결과·재육성 연결·다음 알 | 하나의 작업으로 즉시 저장 |
| 진화 대상 확정 (`PrepareEvolution`) | 대상 이미지 로딩 전 즉시 저장 |
| 진화 보유·회차 연결·이력·선택 (`CompleteEvolution`) | 약 2.2초 실루엣 연출 후 하나의 작업으로 저장 |
| 좌우 반전·UI 배율 | 변경 시 즉시 저장 |
| 창 종료 | 종료 직전 저장 |

같은 폴더에 임시 파일을 작성·flush한 뒤 원본을 원자적으로 교체한다. 임시 파일은 성공·실패와 관계없이 정리한다.

- 준비 저장 실패: 새 `PendingEvolution`을 취소한다.
- 진화 완료 저장 실패: 보유, 회차 연결, `CurrentDex`, `History`, 선택 번호·색상을 복구하고 이미 저장된 진화 대상은 유지한다. 이미지 재시도나 재시작으로 재추첨하지 않는다.
- 부화 저장 실패: 새로 만든 회차를 제거하고 기존 연결·레벨·보유·알을 복구한다.
- 진화는 확정 알, 다른 회차, 다른 색상을 바꾸지 않는다.

## 이전 버전과 main 스키마 3 호환

스키마 0~2는 원본을 `settings.json.schema{버전}.bak`으로 한 번 백업한 뒤 스키마 3으로 저장한다. 이미 있는 백업은 덮어쓰지 않는다.

- 스키마 0의 기존 일반 성장과 스타팅을 복구한다.
- 스키마 1의 일반 보유·성장은 유지한다. 이로치는 새로 지급하지 않으며 기존 준비 알은 커먼 결과로 한 번 확정한다.
- 스키마 2의 **종별 성장 기록은 각각 독립 회차로 유지**한다. 레벨·경험치가 다른 파이리/리자드/리자몽을 임의로 합치지 않는다. 선택·색상·확정 알·화면 설정도 유지한다. 새로 진행하는 진화부터 회차를 공유한다.
- 기존 이브이 진화형 보유·성장은 유지하고, 이미 예약된 진화형 알도 그대로 한 번 부화한다. 새 알 추첨에는 이브이 진화형이 없다.
- main에서 만든 스키마 3의 회차 ID·연결·이력·예약 대상을 그대로 해석한다. 유효한 스키마 3은 단순 조회만으로 다시 저장하지 않는다.
- `NewPreview`는 저장 경로 없는 메모리 전용 설정이다. 테스트·디자이너가 실제 사용자 저장을 읽거나 쓰지 않는다.

## 값 보정과 손상 보호

- `Eggs`는 `0~1`, `EggSeconds`는 유한한 `0~1800`초로 보정한다.
- 스타팅은 일반 보유 목록에 포함한다. 선택이 해당 색상 미보유이면 일반 스타팅으로 복구한다.
- 알 등급·종이 유효하지 않으면 결과를 다시 만든다. 유효한 지역 기본형 알 및 기존 이브이 진화형 예약 알은 보존한다.
- `UiScale`이 지원 값이 아니면 `2`로 보정한다. 누락된 화면 설정은 `FlipHorizontal=false`, `UiScale=2`다.
- 스키마 3의 필수 보유·성장·연결 컬렉션이 누락/null이거나 보유 모습의 연결이 없으면 **Lv.1로 초기화하지 않고 오류**를 낸다. 없는 회차 ID, 잘못된 현재 모습·이력, 음수 경험치/1 미만 레벨, 조건에 맞지 않는 예약 진화도 거부한다.
- 손상된 JSON, JSON `null`, 설정 객체가 아닌 배열·숫자는 원본 그대로 두고 불러오기 오류를 표시한다. 파일 자체가 없을 때만 새 게임을 시작한다.
- 더 새로운 스키마는 덮어쓰거나 백업하지 않고 오류를 표시한다.
