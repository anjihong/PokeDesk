# 저장 데이터

저장 위치: `%LOCALAPPDATA%\DeskPokemon\settings.json`

| 필드 | 의미 |
| --- | --- |
| `SchemaVersion` | 저장 형식 버전. 현재 값 `3` |
| `StarterDex` | 최초 선택한 스타팅의 도감 번호 |
| `SelectedDex` | 현재 화면의 모습 ID. 기본형은 도감 번호, 추가 모습은 별도 고정 ID |
| `SelectedShiny` | 현재 선택이 이로치인지 여부 |
| `Progress`, `ShinyProgress` | 색상별 육성 ID에 대응하는 성장 기록 |
| `GrowthLinks`, `ShinyGrowthLinks` | 색상별 모습 ID에서 육성 ID로 연결 |
| `Owned`, `ShinyOwned` | 색상별 보유 모습 ID 집합 |
| `Eggs` | 보유 알 수. 정상 흐름에서는 `0` 또는 `1` |
| `EggSeconds` | 다음 알까지 누적한 실행 시간(초) |
| `PendingEgg` | 확정된 다음 알의 `Kind`, `Dex`, `IsShiny` |

`UnlockAll`과 `RemainingEggSeconds`는 계산·개발용 속성이며 JSON에 저장하지 않는다.

## 데이터 관계

- `SelectedDex`와 `SelectedShiny`를 한 쌍으로 현재 개체를 식별한다.
- `Progress[육성 ID]`는 `Level`, `Exp`, 이번 육성의 현재 단계 `CurrentDex`, 순서대로 거친 모습 `History`, 확정된 진화 대상 `PendingEvolution`을 저장한다.
- `ShinyProgress`도 같은 구조이며 일반과 독립이다. `GrowthLinks`/`ShinyGrowthLinks`를 통해 여러 모습이 같은 육성을 공유할 수 있다.
- 재육성 시작 시 기본형만 새 기록에 연결하고, 중간 모습은 다시 그 단계에 도달했을 때 연결한다. 기존 진화체는 이전 기록을 유지한다.
- `Owned`와 `ShinyOwned`도 서로 독립된 집합이다.
- `PendingEgg`는 `Eggs`가 0인 대기 중에도 다음 결과를 유지한다.
- `Eggs`가 1이면 타이머를 멈추고 같은 `PendingEgg`를 부화한다.

## 저장 시점

| 변경 | 저장 시점 |
| --- | --- |
| 입력 경험치 | 변경 표시 후 최대 5초 안에 일괄 저장 |
| 알 대기 시간 | 메모리에서 매초 증가, 주기 저장 |
| 알 준비 완료 | 즉시 저장 |
| 도감 포켓몬 선택 | 즉시 저장 |
| 부화 결과·다음 알 결과 | 하나의 작업으로 즉시 저장 |
| 진화 대상 확정 | 이미지 로드 전에 저장, 재시도·재시작 시 재추첨 없음 |
| 진화 완료 | 보유·단계·육성 연결·선택을 하나의 작업으로 즉시 저장 |
| 창 종료 | 종료 직전 저장 |

저장은 같은 폴더에 임시 파일을 만든 뒤 `settings.json`을 교체한다. 기존 파일을 직접 쓰는 중간 상태를 만들지 않는다. 임시 파일은 성공·실패와 관계없이 정리한다.

## 값 보정

- `Eggs`는 `0~1` 범위로 제한한다.
- `EggSeconds`는 유한한 값만 허용하고 `0~1800`초로 제한한다.
- 스타팅은 항상 일반 `Owned`에 포함한다.
- 현재 선택이 해당 색상 보유 목록에 없으면 일반 스타팅으로 되돌린다.
- `PendingEgg`의 등급이나 종이 유효하지 않으면 새 결과를 만든다.

- 구버전은 마이그레이션 전 원본을 `settings.json.schema{버전}.bak`으로 한 번 백업한다.
- 스키마 2 이하의 종별 성장 기록은 독립 육성 기록으로 이전하며 레벨·경험치를 그대로 보존한다. 이후 실제 진화부터 공유한다. 이로치 선택과 유효한 확정 알도 유지한다.
- 알 유효성은 추첨과 동일한 `EvolutionData.EggPool`을 사용한다. 이브이 진화체와 추가 모습의 기본형도 유효하다.
- 육성 연결 대상이 없거나 단계·이력·확정 진화 대상이 유효하지 않으면 불러오기 오류를 표시하고 파일을 덮어쓰지 않는다.
- 스키마 1 저장은 일반 보유·성장 데이터를 유지하고 이로치 데이터를 빈 상태로 추가한다. 기존 준비 알은 커먼 알로 변환하고 결과를 한 번 확정한다.
- 스타팅 번호가 없으면 파이리로 보정한다. 선택 종이 해당 색상에서 미보유면 일반 스타팅으로 되돌린다.
- 저장은 임시 파일 작성 후 원본 교체 방식이다. 부화·진화 저장 실패 시 메모리의 보유·레벨·단계·진화 대상·육성 연결·선택·알 상태도 복구한다.
- 손상된 JSON은 새 게임 흐름으로 시작한다. 현재 앱보다 새 스키마는 덮어쓰지 않고 오류와 함께 종료한다.
