# Windows/macOS 동일 화면 검증

목표는 두 OS에서 같은 앱 화면, 조작, 저장 동작을 제공하는 것입니다.
`MainWindow.axaml`, `StarterWindow.axaml`, 공통 스타일과 자산을 양쪽 실행 파일이 함께 사용해야 합니다.
OS에 따라 달라지는 부분은 전역 입력 API, 권한 안내, 작업 영역 등 플랫폼 연동입니다.

이 문서는 실행할 검증 절차입니다. 체크가 비어 있으면 아직 확인하지 않은 항목입니다.
빌드 또는 headless 테스트 통과를 실제 데스크톱 화면 확인으로 기록하지 않습니다.

CI는 외부 다운로드 없이 고정 테스트 그림으로 스타팅·기본 펫·도감·보유 필터·경험치 툴팁의 1x/2x 렌더와
알 결과의 2x 렌더(총 11개)를 저장합니다. Windows x64·Mac ARM64·Mac x64 사이에서
파일 목록·이미지 크기와 `.layout.json`의 위치·크기·텍스트·폰트·기록된 색상 등을 정확하게 비교합니다.
이미지는 [pixelmatch 0.4.0](https://github.com/whtsky/pixelmatch-py)의 표준 설정
(`threshold=0.1`, `includeAA=false`)으로 안티앨리어싱 경계를 판별합니다.
남은 차이 픽셀은 1% 이하이고, 판별된 경계만 제외한 채널 평균 오차는 1/255 미만이어야 통과합니다.
검정·흰색 배경에서 모두 비교해 투명도 차이도 확인합니다.
원본 MAE와 채널 차이 25/255를 넘는 픽셀 비율은 변경하지 않고 보고서에 참고 수치로 남깁니다.
원본 차이와 경계 분류 이미지도 저장합니다. 이 허용 범위는 CoreText/DirectWrite 글자 래스터화 차이를
다루며 픽셀 단위 완전 일치를 뜻하지 않습니다. 레이아웃·텍스트·색상 스냅샷 차이는 허용하지 않습니다.
`desktop-visual-comparison` 아티팩트에 수치와 차이 PNG가 기록됩니다.
이는 같은 뷰의 렌더링 비교이며, 실제 모니터의 DPI 전환과 OS 창 합성·전역 입력은 아래 절차로 확인합니다.

## 비교 준비

1. 같은 커밋의 Release 빌드를 Windows x64, macOS ARM64, macOS x64에서 준비합니다.
   Mac에서는 `dotnet run`과 별도로 `.app` 패키지 실행도 확인합니다.
2. 기존 세이브를 백업하고 비교 전용 OS 사용자 계정이나 테스트용 저장 데이터를 사용합니다.
   실행 중인 앱을 모두 닫은 뒤 같은 `settings.json`과 다운로드된 스프라이트 캐시를 두 OS에 복사합니다.
   네트워크에서 바뀔 수 있는 외부 이미지까지 같아야 화면 비교가 의미가 있습니다.
3. 바탕화면 배경색, 선택 포켓몬/폼, 레벨·경험치, 보유 목록, 세대 탭,
   알 상태와 패널 열림 상태를 맞춥니다. 랜덤 스타팅 후보나 랜덤 부화 결과는
   서로 다른 데이터가 선택된 상태로 픽셀 비교하지 않습니다.
4. Windows 100% / macOS 1x, Windows 200% / macOS Retina 2x에서 각각 촬영합니다.
   화면의 물리 픽셀 수와 논리 크기(DIP)를 함께 기록합니다.
   모니터를 옮길 수 있으면 1x ↔ 2x 이동 후에도 반복합니다.
5. OS 권한 창, 바탕화면, 마우스 커서를 제외한 앱 영역을 같은 논리 좌표로 자릅니다.
   스프라이트 프레임과 바운스·알 애니메이션 시점도 맞춥니다.
   정지 화면은 상태별 PNG, 애니메이션은 짧은 동영상으로 보관합니다.

네이티브 권한 창의 외형은 OS가 제공하지만 앱 내부 화면은 공통 UI여야 합니다.

## 기능 및 플랫폼 동작

- [ ] 첫 실행에서 스타팅을 하나 선택하면 저장되고, 다시 실행하면 선택 창 없이 같은 펫이 보인다.
- [ ] 스타팅 창을 닫으면 프로세스가 남지 않는다. 이미지 다운로드 실패 시에도 이름으로 선택할 수 있다.
- [ ] 일반 PNG atlas 종, 확장 atlas 종, GIF fallback 종과 폼을 열어 투명도·프레임 잘림·잔상이 없는지 확인한다.
- [ ] 빠르게 포켓몬과 세대를 바꾸어도 늦게 완료된 다운로드가 현재 선택을 덮어쓰지 않는다.
- [ ] 다른 앱에서 키를 1회 누르고 떼면 경험치 +1과 바운스가 1회 발생한다.
  키를 길게 눌러 자동 반복이 발생해도 경험치가 계속 증가하지 않는다.
- [ ] 다른 앱에서 좌/우/가운데 버튼을 각각 1회 클릭하면 경험치가 각각 1회 증가한다.
  앱 자신의 버튼을 클릭할 때 전역 입력과 로컬 입력이 겹쳐 +2가 되지 않는다.
- [ ] 레벨 × 30회의 입력마다 레벨업하며, 포켓몬 교체 후 각자의 경험치·레벨이 유지된다.
- [ ] 경험치 바에 커서를 올리면 현재/필요 경험치가 표시된다. 0 경험치에서도 표시되며, 열린 상태에서 레벨업하면 새 수치로 갱신된다.
- [ ] 도감을 열면 X 좌표를 유지하며 패널 높이만큼 위로 이동하고, 닫으면 원위치로 돌아온다. 반복 클릭·빠른 반전·화면 상단에서도 위치가 누적해서 어긋나지 않는다.
- [ ] 창의 빈 부분을 드래그할 수 있고, 도감/알/버튼 조작이 창 드래그로 바뀌지 않는다.
- [ ] 다른 일반 창 앞에 펫이 유지되고 작업 표시줄/Dock에 불필요한 창 항목이 생기지 않는다.
  다른 모니터 이동, 패널 열기, 크기가 다른 포켓몬 선택 후 작업 영역 밖으로 잘리지 않는다.
- [ ] 앱 실행 시간 30분 후 알 1개가 지급되고 부화 전에는 타이머가 멈춘다.
  절전·복귀 후 경과 시간이 과도하게 누적되지 않는다.
- [ ] 테스트 알 지급으로 신규 획득·중복 획득을 각각 확인한다. 중복은 해당 포켓몬 레벨 +1이다.
- [ ] 알을 연속 클릭해도 중복 부화하지 않고 결과 표시 후 정상 대기로 돌아온다.
- [ ] 종료·재실행 후 선택, 보유 목록, 레벨/경험치, 알과 누적 시간이 유지된다.
  기존 Windows WPF 세이브를 복사해도 스타팅/보유/레벨 마이그레이션이 정상이다.
- [ ] 자산을 한 번 받은 뒤 네트워크를 끊어 캐시 재사용을 확인한다.
  캐시에 없는 자산 다운로드가 실패해도 조작과 종료가 가능하다.
- [ ] Debug에서만 초기화·전체 해금·배치 편집 메뉴가 나타난다.
  전체 해금 토글을 껐을 때 원래 보유 상태로 돌아가며 치트 상태가 저장되지 않는다.
- [ ] Debug 배치 저장은 `LayoutDefaults.cs`만 변경하고, 초기화는 확인 후 스타팅 선택으로 돌아온다.
  Release에 개발 전용 메뉴가 나타나지 않는다.

## macOS 입력 권한

권한 테스트는 가급적 앱을 처음 실행하는 테스트 계정/VM에서 수행합니다. 이미 허용된 개발 머신만으로
최초 요청·거부 동작을 판단하지 않습니다. `.app`을 고정된 위치에 놓고 다음 흐름을 확인합니다.

- [ ] **미허용**: 전역 입력이 비활성임을 알 수 있고, 도감·알·종료 등 나머지 앱 기능은 동작한다.
- [ ] **거부**: 권한 거부 후 앱이 종료되거나 요청 창을 반복해서 띄우지 않는다.
- [ ] **허용**: 시스템 설정 → 개인정보 보호 및 보안 → 입력 모니터링에서 DeskPokemon 허용 후
  완전히 종료·재실행하면 다른 앱의 키/클릭에도 반응한다.
- [ ] **취소**: 실행 중 권한을 해제한 상태와 재실행 후를 각각 확인하고, 전역 입력이 멈추어도 앱 조작은 유지된다.
- [ ] 터미널에서 `dotnet run`한 경우와 `.app`을 실행한 경우의 권한 대상 이름을 기록한다.
  개발 호스트의 권한이 `.app`에도 자동으로 적용된다고 가정하지 않는다.
- [ ] 부여한 권한과 실행 위치가 같을 때 앱 재실행 후 중복 이벤트나 유실이 없다.

입력 권한은 키 입력·클릭 **횟수에 따른 반응**에 쓰입니다. 입력 문자열의 수집·저장·전송이 추가되지
않았는지도 변경 검토에서 확인합니다. 읽기 전용 CGEventTap과 Input Monitoring의 관계는
[Apple DTS 설명](https://developer.apple.com/forums/thread/811443)을 참고하세요.

모든 플랫폼을 직접 실행하기 전에는 “동일 화면 검증 완료”로 표시하지 않습니다.
